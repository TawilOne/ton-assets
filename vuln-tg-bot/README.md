# 🕳 VulnShopBot — дырявый Telegram-бот для тренировки

Намеренно уязвимый бот-магазин. В нём спрятано **11 флагов** вида `FLAG{...}`:
каждый добывается своей уязвимостью. Найденный флаг сдаётся командой `/flag`,
прогресс показывает `/score`.

> ⚠️ **Бот уязвим к удалённому выполнению кода.** Запускай только в Docker,
> только с `ALLOWED_USERS` (без него бот не стартует) и никому не давай токен.
> Не разворачивай на сервере, где лежит что-то важное.

## Запуск

1. Создай бота у [@BotFather](https://t.me/BotFather) и получи токен.
2. Узнай свой Telegram ID (например, у @userinfobot).
3. Настрой и запусти:

```bash
cp .env.example .env      # впиши BOT_TOKEN и ALLOWED_USERS
docker compose up -d --build
```

Без Docker (не рекомендуется): `pip install -r requirements.txt && BOT_TOKEN=... ALLOWED_USERS=... python bot.py`.

Флаги генерируются случайно при первом запуске (`data/flags.json`), поэтому
в коде их нет. Сбросить прогресс: `docker compose down -v`.

## Режимы игры

- **Black box** — не открывай `bot.py`, ищи через команды бота. Это сложнее и интереснее.
- **White box** — читай код и ищи дыры как на код-ревью.

## Задания и подсказки

| # | Флаг | Тема | Подсказка |
|---|------|------|-----------|
| 1 | `sqli` | SQL Injection | Поиск собирает запрос из твоего текста. В базе есть таблица, которую витрина не показывает. |
| 2 | `idor` | IDOR | Номера заказов идут по порядку. Кто сделал самый первый? |
| 3 | `callback` | Подмена callback_data | Кнопки присылают боту данные. Что в них лежит и проверяет ли сервер это? Понадобится userbot (Telethon / Pyrogram). |
| 4 | `logic` | Бизнес-логика | В VIP пускают с миллионом. Переводы проверяют, хватает ли денег, но всё ли проверяют? |
| 5 | `admin` | Broken access control | `/admin` как-то решает, кто админ. Какие данные о тебе бот получает от Telegram и какие из них ты можешь поменять? |
| 6 | `path` | Path Traversal | `/doc` читает файлы и фильтрует `../`. Фильтр проходит по строке только один раз. Флаг лежит в `data/secret/flag.txt`. |
| 7 | `cmdi` | Command Injection | `/ping` вызывает shell. Чёрный список запрещает `;` и `&`, но в shell есть и другие спецсимволы. Ищи `cmdi_flag.txt`. |
| 8 | `pickle` | Небезопасная десериализация | Посмотри, что отдаёт `/export`. Что будет, если `/import` получит другой объект? Ищи `pickle_flag.txt`. |
| 9 | `ssti` | Server-Side Template Injection | Приветствие поддерживает `{{ ... }}`. Какие ещё переменные видны шаблону? |
| 10 | `debug` | Раскрытие информации | Что бот показывает, когда падает? |
| 11 | `brute` | Брутфорс без rate limit | Промокод короткий, а попыток сколько угодно. |

Подробные разборы лежат в [SOLUTIONS.md](SOLUTIONS.md). Не открывай, пока не застрял!

## Что дальше

Когда найдёшь всё, попробуй **починить** каждую дыру в `bot.py`
(параметризованный SQL, проверка владельца заказа, цена из БД, а не из кнопки,
`amount > 0`, админ по ID, `os.path.realpath` + проверка префикса,
`subprocess.run([...])` без shell, JSON вместо pickle, `SandboxedEnvironment`
или вообще без шаблонов, общий текст ошибки, ограничение попыток) и убедись,
что старые эксплойты больше не работают.
